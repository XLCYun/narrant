# Use a GitHub App with Device Flow

Authenticate private Pull Request discovery through a GitHub App using Device Flow,
with repository permissions limited to read-only metadata and pull requests. GitHub no
longer supplies repository contents: Narrant obtains code through the user's local
clone and Core Git transport, so requesting contents permission would exceed the
platform access actually required.

## Consequences

- The application must guide users through both GitHub App installation and device authorization when required.
- Organization policy may require an owner to approve the installation before private repositories become accessible.
- Enable expiring user access tokens; the Rust side refreshes them with rotating refresh tokens and requests authorization again only when refresh fails.
- Access tokens, refresh tokens, and expiry metadata must remain in the Rust side and be stored in the operating system credential store.
- GitHub App credentials authorize GitHub platform operations such as Pull Request
  discovery and collaboration metadata. They are not injected into Core Git fetch;
  repository transport continues to use the user's existing Git credentials, SSH
  configuration, credential helpers, proxy, and certificate environment.
- Treat the operating-system user and its local repositories as the security boundary.
  Signing out removes stored credentials and pending authorization state but preserves
  Repository Entries, Reviews, Snapshots, worktrees, and cached Pull Request metadata;
  deleting a Repository Entry is the future cleanup boundary for its local review
  history.
- Compile the public GitHub App client ID and app slug into release builds. End users do not configure environment variables, and no client secret or private key is shipped.
- Device authorization UI warns users to use only a code generated by their current Narrant session and to verify the GitHub App name before approving it.
- Authorization Code with PKCE remains a future option if Narrant gains a confidential backend. GitHub currently requires a client secret for GitHub App authorization-code exchange and refresh, which a native public client cannot keep secret.
