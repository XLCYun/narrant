# 代码结构变更视图

通过 `grill-with-docs` 完成 Q1–Q21 的产品决策，用户已于 2026-09-08 整体确认本规格及 [ADR-0030](../adr/0030-encapsulate-code-structure-analysis.md)。具体依赖通过实现前的集成验证确定，不重新打开已确认的产品范围。

## 目标与首版范围

在 Narrant 当前 Review 中增加 **Code Structure View**，让审阅者从类、函数等原生代码声明及其关系理解本次变更，辨认新增、删除、修改、改名、移动和文档变化，并从图中打开完整文件 Diff 定位相关行。

首版支持 TypeScript / JavaScript（含 TSX / JSX）与 Rust。基础结构与常见跨文件关系使用内置分析，无需配置语言服务器；更深入的语言服务器集成属于后续功能。规模验收先以 Narrant 自身为准。

完整领域术语见 [`CONTEXT.md`](../../CONTEXT.md)。实现 tickets 使用 GitHub Issues，并链接本文对应范围和验收项；本文是跨 ticket 的产品范围来源。

## Review 与版本来源

- Overview、File Changes、Code Structure View 是同一 Review Snapshot 的平级视图；切换视图不创建新的 Review。
- 沿用当前 Comparison Base → Head 的比较规则，本地分支与 Pull Request 行为一致。所有结构、关系和 Peek 来源固定到该 Snapshot 的精确版本。
- 分析范围覆盖仓库内未修改代码，以发现变更结构的调用者、被调用者、所属类型等上下文。显示一跳不意味着只解析一跳或只读 File Changes。
- Before 与 after 分别使用各自版本的源码、导入及项目配置。只有 Head 的 Review Workspace 不能用于解释 before 的关系。
- 两侧是同一本地 Git 对象库中的逻辑源码快照，不要求再克隆仓库或为结构分析建立两个 checkout。按固定 commit 枚举 tree、读取 blob，将内存中的源码交给解析器；跨文件索引分别使用各侧路径与配置。Tree-sitter 可直接接收字符串或自定义文本读取接口。[解析输入说明](https://tree-sitter.github.io/tree-sitter/using-parsers/2-basic-parsing.html)。
- 不增加独立版本选择、工作区未提交改动比较或图历史系统。

## 原生结构与组织

| 结构 | 呈现规则 |
| --- | --- |
| 类、struct、trait、interface、type | 保留原生种类与签名；不统一改写为类 |
| 方法、字段及类型成员 | 放在所属类型中，可折叠并独立定位 |
| 独立函数、具名箭头函数、具名 React 组件 | 按原生函数结构呈现；React 组件不引入特殊分析模型 |
| Rust impl | 同一类型汇总为一个类型节点，内部保留各 impl 分组、trait 名称和源码来源 |
| 枚举、顶层常量 | 纳入原生结构 |
| 模块 / 命名空间 | 作为结构容器 |
| 嵌套具名函数 | 按所属层级呈现和折叠 |
| 普通局部变量、匿名回调 | 不独立成为图节点；源码变化与调用仍可通过所属声明或文件上下文访问 |

跨文件类型或多个 impl 不得压成一个源码区间。不同类型、不同 trait 的同名方法不能仅凭名称合并。匿名回调的调用位置与来源需保留；折叠匿名节点不等于可以把回调执行误称为外层函数的直接调用。

初始按模块 / 文件分组并自动布局，聚焦变更结构、关系变化及一跳上下游；只有关系变化时，其未改端点作为上下文进入初始集合。变化成员默认展开，未修改成员折叠；可继续展开上下游，支持名称搜索、结构类型和变化类型过滤。跨文件 Rust 类型在类型声明所属分组中汇总，并提供各实现来源；只存在旧侧的类型使用旧侧所属分组。

## 变更判定与汇总

- 新增和删除分别表示声明在相应版本中确实不存在；解析失败或尚未分析不构成不存在的证据。
- 可可靠配对时保留结构连续身份，单独标记改名或移动；不可靠且两侧分析覆盖足够时保留新增与删除，不强行合并。
- 正文或签名变化标记修改。改名、移动、修改、文档变化可以同时出现，不因单一状态枚举丢失事实。
- 纯格式变化不标结构修改；关联注释变化单列 **Documentation Change**，仍属于初始变更焦点并可查看原始文本差异。
- 父级显示“包含 N 项变化”。仅在父级自身声明也发生变化时另标自身修改；不因源码区间包含变化的具名子声明而重复计算。
- 总数按实际变化声明去重，一个声明的多个标签不增加声明总数。关系变化另行统计，不混入声明数量；折叠、展开和多 impl 汇总不复制声明。
- 未修改端点作为 **Structure Context**，不会因它调用或被调用的代码有变化而自动成为 **Structure Change**。

“纯格式”不得实现为删除所有空白后比较。字符串、模板字符串和 Rust raw string 内部空白，以及会改变 TS / JS 自动分号插入结果的换行，仍按实际代码变化处理。Peek 始终使用原始源码。

配对算法和阈值通过样例验证决定。最低防误配要求包括重复同名函数、完全相同的多个函数体、同名重载，以及移动同时改名并修改正文；多个合理候选不得强行选一个。分析覆盖不足时按“不完整”处理，不能走增删回退。

## 关系、确定性与连线

| 关系 | 默认呈现 |
| --- | --- |
| 归属 | 通过分组 / 层级表达，并保留前后归属 |
| 继承 / 接口或 trait 实现 | 默认显示，可按关系类型切换 |
| 调用 | 默认显示所选节点的一跳调用，可切换为当前图的全部调用或隐藏 |
| 类型引用 | 独立开关，默认关闭 |
| import / 模块依赖 | 独立开关，默认关闭；以对应模块 / 文件容器为端点 |

同图展示 before / after 关系并集，以不同颜色和图例区分新增、删除、保留关系。一跳上下文包含旧、新两侧；不能只展开 after 而漏掉删除的调用或旧归属。主结构节点只出现一次：优先放在新侧归属下，删除结构放在旧侧；移动结构保留原位置入口及旧、新归属关系。

**Relationship Change** 可以单独成为可发现的变化，源码未改的端点仍属于上下文。变化类别和关系类型是不同维度；颜色、图例 / 文字、关系类型及方向共同表达含义，明暗主题均需验收。

类型引用和 import 连线关闭时仍保留对应关系变化的统计与定位入口；隐藏连线不能让关系单独变化成为不可发现的空图。

关系按匹配后的端点和关系种类组织，保留各调用 / 引用的原始位置。多个调用点可汇总到一条关系边，查看时能区分来源；仅行号位移不应制造关系新增 / 删除。

关系结果区分：

- **已解析目标**：依据当前侧的词法作用域、导入、限定名或其他明确证据连接到目标。
- **候选目标**：保留可能的目标及来源，默认隐藏，可单独开启；不得呈现为已经确定的调用。
- **未解析**：明确提示位置及原因；不把缺少边解释为“没有调用”。

只有相关侧的关系分析覆盖足以确认缺失时，才标记关系新增 / 删除。目标由确定变为未知、解析错误或配置缺失不能伪装成关系删除。语法解析完整也不代表调用解析完整。

## 仓库外目标与首版分析覆盖

第三方目标显示名称和所属包的外部节点，可隐藏。首版不扫描 node_modules、Cargo registry 等仓库外依赖源码，不展开其内部调用关系。外部名称不保证有可打开的本地定义；不提供虚假的源码定位。

首版的“常见跨文件调用”至少用以下正例验证，不允许把所有调用统一标未知来满足部分结果协议：

- 当前侧词法作用域中可明确绑定的具名函数调用，并正确处理同名遮蔽。
- 仓库内通过显式导入及别名连接的函数调用；包括 Narrant 使用的 TS 路径别名和 Rust 模块 / use 路径。
- 目标归属明确的类型限定调用、静态 / 关联函数，以及能够确定所属类型的 this / self 方法调用。
- 跨文件 impl 的方法归属、显式继承 / 实现、类型引用和 import 依赖。

上述为内置分析的最低行为契约。动态属性、反射、无法静态绑定的对象调用、复杂类型推断、动态 trait 派发或宏生成的声明，不承诺穷尽运行时目标；按证据返回候选或未解析。不能从“语法包支持某语言”推导“所有关系均可精确解析”。

测试和报告必须分别说明结构提取与关系解析的覆盖。首版没有语言服务器安装、配置或运行管理 UI；未来语义 provider 在内部 adapter 扩展，不要求图和 Peek 重写语言逻辑。

## Structure Peek

- 在图下方打开可调整高度的面板，显示相关文件的完整 Diff，并定位 / 高亮相关行；不裁剪为方法片段。
- 方法或函数直接进入对应源码位置。默认新侧；删除结构进入旧侧；两侧各自保留真实行号范围。
- 点击关系边查看调用 / 引用发生的位置；新增和保留关系默认新侧，删除关系默认旧侧。多个来源提供位置列表，选择后打开该位置所属文件的完整 Diff；目标定义作为独立导航入口，不能替代关系发生位置。
- 真实文件 rename 沿用 File Change 的 oldPath / path。结构从 A 文件移动到 B 文件时提供“原位置 / 新位置”切换，各自显示该文件真实 before / after，默认新位置；不把 A-before 与 B-after 的全文伪装成一个文件变化。
- 聚合类型提供类型声明和各 impl / 声明片段的位置列表，默认类型声明文件；具体成员直达自身文件。不同来源不拼成虚拟文件。
- 未修改上下文文件按 Snapshot 两侧固定版本读取，标注未变更；不生成虚假 File Change。外部目标没有本地来源时说明原因。
- Peek 选择、加载和滚动独立于 File Changes 当前选择；对真实 File Change 提供显式“在 File Changes 中打开”。未改上下文在 Peek 中阅读。
- Monaco 模型和 Diff 就绪后定位；窄窗口使用单栏，宽窗口沿用可用的单双栏设置。关闭保持图视野，键盘关闭后焦点回到触发节点。
- 一侧源码不可用时明确标明，不能当作空文件；另一侧仍可读取则继续显示。

完整文件方案复用现有 Monaco Diff 与原文件行号，省去方法切片和切片行号偏移处理；仍需新增定位请求、未修改文件读取、多来源切换和独立 Peek 状态。

## 容错、进度与生命周期

Tree-sitter 提供语法错误恢复，以 `ERROR` 和可能的零宽度 `MISSING` 节点表达问题；仅查询 ERROR 无法覆盖所有 MISSING。应用复用它的恢复结果，不另写语言专用语法修复系统。[错误节点说明](https://tree-sitter.github.io/tree-sitter/using-parsers/queries/1-syntax.html)、[Rust Node interface](https://docs.rs/tree-sitter/latest/tree_sitter/struct.Node.html)。

- 提取完整可识别且来源明确的声明，同时记录文件、侧别、错误范围和原因；部分出错不丢弃其他可信结果。
- 受损声明或所属作用域无法可靠识别时，保留相关未知状态。局部节点无错误，不自动证明其归属和关系正确。
- Git 明确记录的文件缺侧与解析缺失、语言不支持、文件类型不支持、分析取消、资源限制、Git 对象不可用分别表达。
- 源码可读时始终保留文件入口。Peek 显示原始文件，不显示 parser 恢复时插入的虚拟内容。
- 后台分析显示进度与覆盖，支持取消；File Changes 保持可用。取消后的部分结果不能标成完成，允许显式重试。
- 切换已打开 Review 保留各自图视野、展开、选择及 Peek 运行状态。
- 显式刷新 Snapshot 后重建派生内容；旧异步结果不能覆盖新图。显示偏好可保留，失效选择与位置清理或重新验证。
- 沿用进程内 Open Review Set，不新增独立图历史或跨进程恢复。缓存优化不得突破精确 Snapshot 的来源约束。
- 可选分析失败不回滚 Review 刷新，也不阻塞普通文件阅读。

## 规模与交互验收

用户选择先以 Narrant 自身为唯一代表仓库，不以另找大型仓库作为实施前提。分析范围仍覆盖该仓库两侧的支持语言源码，不以当前变化文件数替代仓库规模。

调查基线为 Git commit `da4f583089350b6fe8632fb83dcc9d7558e77286` 的 tracked blobs，包含测试、开发脚本、类型声明及已跟踪生成源码；不包含未跟踪文件、安装依赖和构建输出。物理行数包含空行和注释。

| 语言 | 文件数 | 源码字节 | 物理行数 |
| --- | ---: | ---: | ---: |
| TypeScript（.ts / .tsx） | 152 | 1,902,555 | 46,305 |
| JavaScript（.js / .mjs） | 46 | 378,997 | 8,720 |
| Rust（.rs） | 177 | 1,657,098 | 45,394 |
| 合计 | 375 | 3,938,650 | 100,419 |

其中生成文件 [`file-type-icon-manifest.ts`](../../src/lib/file-type-icon-manifest.ts) 占 934,138 字节、25,527 行，应在性能报告中单独标识，不能静默排除以缩小规模。后续固定被测 Snapshot 两侧版本后重新统计。

真实样例包括跨文件 `ReviewLifecycle` / impl、[`sonner.tsx`](../../src/components/ui/sonner.tsx) 的具名箭头组件与第三方别名，以及 [`branch-relation.tsx`](../../src/components/branch-relation.tsx) 的 `branchName` 和其他文件中的调用。组件样例验证原生函数提取；不将 JSX 使用自动等同于已解析的普通函数调用。

后台索引与图呈现分开。大图按批次展开，显示已呈现 / 待展开数量；保留搜索及继续展开入口，不因节点展示上限静默漏变更。资源限制导致未分析时，显式报告受限范围和继续 / 重试方式，不能把未分析项计为未变更。

集成验证报告应固定 Git revisions、机器和构建模式，记录源码规模、首次可用结果、完整分析耗时、峰值内存、取消响应及展开 / 搜索 / Peek 的交互表现。缓存命中和未命中分别测量。具体批次、缓存和超大文件预算据实测确定并记录，不能通过降低已确认的分析范围达标。

## 代码现状与架构决策

[ADR-0030](../adr/0030-encapsulate-code-structure-analysis.md) 确定使用一个对外提供结构分析结果和源码访问能力的模块，内部复用多语言提取包，并以 TS / JS 语言族及 Rust adapter 补足差异。

对外结果包含声明、原生种类、签名、所属结构 / 实现组、各源码片段、前后变化、关系证据和覆盖状态。第三方 AST 节点、查询语法和 provider 句柄留在内部；UI 不按扩展名重算归属或变化，也不从空字段猜增删改。调用方无需编排 parser 启动、索引、配对和关系解析顺序。

与现有代码的衔接：

- [`ReviewView`](../../src/review/types.ts) 与 [`ReviewReader`](../../src/components/review-reader.tsx) 当前只有两个视图，需要增加结构视图及其导航状态。
- [`SnapshotContentReader`](../../src-tauri/src/review/content/comparison.rs) 当前只允许读取 File Changes；分析和上下文 Peek 需要固定两侧 tree 的发现 / 读取能力。
- [`BabysitDiffEditor`](../../src/components/babysit-diff-editor.tsx) 已支持完整文件 Diff，尚无外部结构定位请求。
- `ReviewLifecycle` 的 impl 分布于 [`mod.rs`](../../src-tauri/src/review/lifecycle/mod.rs)、[`presentation.rs`](../../src-tauri/src/review/lifecycle/presentation.rs)、[`refresh.rs`](../../src-tauri/src/review/lifecycle/refresh.rs)、[`workspace.rs`](../../src-tauri/src/review/lifecycle/workspace.rs)，可验证多来源类型聚合。
- 沿用 [ADR-0010](../adr/0010-use-current-three-dot-comparisons.md) 的比较规则、[ADR-0009](../adr/0009-do-not-pin-snapshot-git-objects.md) 的历史对象可用性、[ADR-0012](../adr/0012-separate-review-refresh-from-analysis-readiness.md) 的分析降级，以及 [ADR-0014](../adr/0014-use-a-typed-tauri-transport-and-domain-application-adapters.md) / [ADR-0019](../adr/0019-organize-rust-backend-by-capability.md) 的模块组织方式。

## 依赖调查与选择准则

| 候选 | 已查证的可复用能力 | 集成时必须验证 |
| --- | --- | --- |
| Tree-sitter | 多语言 grammar、Rust binding、增量语法树和错误恢复 | 目标 grammar 与 runtime 的兼容性及声明提取 |
| tree-sitter-language-pack | 统一 process interface；结构层级、名称、签名、源码范围、导入 / 导出等 | 首版全部原生声明、错误范围、静态离线打包、包体积和目标平台；不能假设自带调用图 |
| ast-grep-language + ast-grep-outline | 统一语言入口、内置结构提取规则、可嵌入 Rust crate | 字段与原生声明覆盖、Rust impl 的关系映射、准确范围；outline 明确不提供调用图或类型解析 |

优先验证现成包覆盖，补足确认缺失的语言规则。首个实现准备任务固定候选版本，验证上述接口及断网运行，记录选择依据；包选择保留在内部，不更改本规格的声明、关系和 Peek 契约。当前只完成文档与源码调查，未运行依赖集成验证。

language-pack 默认会下载 grammar，也提供按语言子集静态构建路径；首版开箱即用要求解析资源随应用可用，不把首次联网下载或手动安装变成隐藏前提。[构建说明](https://docs.tree-sitter-language-pack.xberg.io/guides/building/)。

Tree-sitter 是解析库，不需要语言服务器。语言服务器是对编辑器提供补全、定义跳转、引用和诊断等能力的分析工具，LSP 是通信协议；它可以利用解析器及更深入的类型 / 项目分析，具体能力取决于实现。首版不依赖 LSP，也不把所有语义解析等同于必须使用 LSP。[Tree-sitter](https://tree-sitter.github.io/tree-sitter/)、[语言服务器说明](https://code.visualstudio.com/api/language-extensions/language-server-extension-guide)。

其他已核验来源：[language-pack 结构提取](https://docs.tree-sitter-language-pack.xberg.io/guides/intelligence/)、[其单文件分析契约](https://docs.tree-sitter-language-pack.xberg.io/concepts/code-intelligence/)、[ast-grep outline](https://ast-grep.github.io/guide/outline-code)、[outline Rust API](https://docs.rs/ast-grep-outline/latest/ast_grep_outline/)、[TypeScript 符号与类型查询](https://github.com/microsoft/TypeScript/wiki/Using-the-Compiler-API#type-checker-apis)。这些是候选能力证据，不是 Narrant 集成完成证明。

## 验收场景

| 编号 | 场景 | 必须成立的结果 |
| --- | --- | --- |
| A1 | 视图切换、ref 移动、分析期间刷新 Snapshot | 图 / Peek 不混版本，旧结果不覆盖新图，切视图不新建 Review |
| A2 | TS / JS / TSX / JSX / Rust 原生声明 | 保留所需种类和层级，具名结构有准确源码位置 |
| A3 | 未修改文件中的调用者、被调用者和类型 | 可发现并继续展开；分析不限于 File Changes |
| A4 | 确定、候选、未解析调用 | 明确区分；候选默认隐藏并可开启；不会用全未知冒充内置常见调用支持 |
| A5 | 改名 / 移动、重复同名、相同函数体、重载 | 可靠时保留身份和两侧位置；歧义不强行配对；覆盖不足不误报增删 |
| A6 | 安全缩进、字符串内部空白、语法相关换行 | 仅真正纯格式变化被忽略；实际语法或字面量变化仍识别 |
| A7 | 仅注释变化，以及注释与正文同时变化 | 文档变化可发现并可 Peek；正文变化与文档标签不互相覆盖 |
| A8 | 跨文件多个 impl、不同 trait 同名方法 | 类型汇总且保留实现分组；不复制或错误合并成员 |
| A9 | 嵌套具名函数、匿名回调变化及调用 | 具名声明按层级；匿名代码来源仍可访问且不伪称直接调用 |
| A10 | 同时改名 / 移动 / 修改，父子分别变化 | 多标签、去重计数、父级自身与包含变化区分，折叠不改变总数 |
| A11 | 调用 A 改为 B、关系单独变化、目标转为未知 | 新旧边及上下文可见，颜色 / 图例区分；关系单独变化有初始入口，关闭类型 / import 连线不隐藏变化统计；未知不伪装删除，未改端点不伪装正文修改 |
| A12 | 从方法或多调用点关系进入 Peek，切换来源，再关闭 | 底部完整文件 Diff 定位对应声明或调用 / 引用发生位置，旧新侧选择正确；图视野保留，状态不误改 File Changes |
| A13 | ERROR / MISSING、单侧对象不可用、取消与资源限制 | 保留可信结果与原因；未知不算不存在，原文件不被恢复内容替换 |
| A14 | 无语言服务器、离线首次进入、分析期间阅读文件 | 核心能力可用、有进度可取消、不阻塞文件阅读、不隐含 grammar 下载要求 |
| A15 | 类型引用、import、外部目标 | 类型引用与 import 的独立开关默认关闭；外部目标按当前可见关系呈现并可隐藏，不扫描依赖源码或伪造定义位置 |
| A16 | 文件 rename、函数跨文件移动、多来源类型、未改上下文 | 正确切换真实文件与来源，不合成虚假 File Change 或虚拟文件 |
| A17 | 中文、CRLF、空侧、尚未就绪的 Diff、窄窗口 | 使用原文件行号并在就绪后定位，缺失与不可用不同，单栏 / 双栏阅读可用 |
| A18 | Narrant 全仓库两侧、搜索展开、大量变化节点 | 完整范围有覆盖报告；分批不静默漏项；记录耗时、内存和交互 / 取消结果 |

跨语言分析从模块公开 interface 验证；语言私有实现测试按仓库约定放到独立测试文件，Rust 测试收在模块内 tests/。UI 测试验证呈现和交互，不在前端重复实现语言规则。

前端布局、响应式、折叠、弹层、长内容和交互状态必须使用应用内浏览器真实渲染验收；Tauri 不可直接运行时使用通用 Preview Harness。覆盖宽 / 窄窗口、长 / 短内容、关系开关、部分结果、Peek 展开与多来源切换，并检查 DOM 和关键位置。恢复默认 viewport，不提交一次性预览页。

实施后完成受影响测试、类型检查、Lint 和生产构建。Cargo 一律经 scripts/cargo-agent.sh；按每个 Issue 的验证节奏执行，避免并发冷编译；不手动触发 quality-gate。
